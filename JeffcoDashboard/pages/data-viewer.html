📋 Dashboard Overview

The Jeffco Facility Planning Dashboard is a planning tool that helps compare facilities, capacity, and program needs across schools. The main workflow has four process steps plus a School Project List:

  • Step 1 — School-level data review and comparison
  • Step 2 — Interactive map for geographic exploration
  • Step 3 — Strategic sorting (decision categories via thresholds)
  • Step 4 — Prioritization within strategy groups
  • School Project List — Per-school assets, deficiencies, and projects

✅ Key features

  • Interactive map to explore schools spatially (filters, popups, overlays).
  • Flowchart to explain why a school received its Step 3 decision category.
  • Strategic sorting results panel with category summaries and per-school outcomes.
  • School Project List to review per-school projects and cost rollups (including priority subtotals).
Tip: Open the Workflow & Steps tab for what each step does, assumptions, and when to use the map vs. flowchart. The Closure Scenarios student-reassignment tool now lives as a standalone app in the ClosureScenarioModule/ folder (open index.html from that directory over HTTP).

Dashboard workflow

This tab explains how the Jeffco Facility Planning Dashboard is organized: what each process step does, what assumptions drive the calculations, and how the optional views (map, flowchart, project list) fit together.

The overview below is shown by default. Use the dropdown to read about a specific step in more detail—each section covers purpose, assumptions/methodology, and how it connects to the rest of the tool.

What this dashboard is for

The tool supports facility planning conversations by combining school-level indicators, geographic context, rule-based strategy sorting, and within-group prioritization. It does not produce final designs or funding decisions—it surfaces patterns and recommended pathways for discussion.

Recommended sequence

  1. Step 1School-level data — Review enrollment, utilization, capacity, facility scores, and projections for one school (and optionally compare peers).
  2. Step 2Interactive map — Explore geography, articulation areas, filters, and spatial relationships across the district.
  3. Step 3Strategic sorting — Apply threshold-based logic to assign each school a decision category (expansion, maintenance/investment, or closure/consolidation).
  4. Step 4Prioritization — Rank schools within a selected strategy group using weighted criteria.
  5. Project listSchool Project List — Drill into asset condition, deficiencies, and project history for individual schools (separate page).
Decision categories vs. projects: Categories describe a recommended planning pathway. They are not capital projects. The School Project List holds facility and project detail when you need cost and asset context.

Step 1 — School-level data

What it does

  • Select a school and view key indicators in a focused layout (no map or side panels).
  • Optionally compare to other schools in the same articulation area.
  • Open the School Project List for the selected school from this step.

Assumptions & methodology

  • Metrics come from Decision Data Export.csv, with articulation area names joined from Map_Export.csv.
  • Include PK toggles whether pre-K counts toward enrollment, utilization, and available seats.
  • Use Educational Capacity switches the capacity denominator when that field is available.
  • Utilization and available seats use the active capacity source and enrollment fields (CurrEnrollment, CurrPKEnrollment, projections).

What it does not do

  • Does not assign decision categories (Step 3).
  • Does not rank schools district-wide (Step 4).
  • Does not replace asset-level costing in the School Project List.

Step 2 — Interactive map

What it does

  • Displays schools as points on a base map for geographic exploration.
  • Filters narrow the visible set by level, enrollment, utilization, seats, and more.
  • Articulation area overlay shows boundaries and member schools.

Assumptions & methodology

  • Locations and polygons come from Map_Export.csv and related map layers.
  • At Step 2 the map emphasizes spatial context before strategy outcomes are applied.

Step 2 map vs. Step 3 map

  • Step 2 — Explore geography and find schools of interest; symbology is not driven by strategic sorting.
  • Step 3 — Same map canvas, but points are colored by decision category from threshold-based sorting.

Step 3 — Strategic sorting

What it does

  • Assigns each school a decision category through four flows (routing, expansion, maintenance/investment, closure/consolidation).
  • Threshold sliders in Controls recalculate Strategic Sorting: Results on the right.
  • View outcomes on the map (district-wide) or flowchart (one school's path).

Map view vs. flowchart view

Both use the same sorting logic. Switch from the menu (Map / Flowchart) during Step 3.

Map view

Best for: District-wide patterns and geographic context.

  • All schools visible, colored by strategy group.
  • Filters and popups support exploration.
  • Answers: Where are schools in each category?

Flowchart view

Best for: Explaining one school's outcome.

  • Select a school to trace decision nodes.
  • Highlights active branches and threshold values.
  • Answers: Why did this school land in this category?

Assumptions & methodology

  • Flow 1: Utilization, growth, enrollment by level, and distance to underutilized schools route into expansion, maintenance, or closure paths.
  • Flow 2: Attendance area enrollment, composite building score, and educational adequacy refine expansion outcomes.
  • Flow 3: Building score and adequacy distinguish maintenance vs. targeted/major investment.
  • Flow 4: Scores and distance to welcoming schools inform closure/consolidation categories.
  • Building composite score: FCI 30%, EUI 15%, age 15%, last renovation 10%, FCS 10%, work orders 20%.
  • Schools with Include_Flow_Chart = No are excluded. Results are deterministic for a given data snapshot and slider set.

Decision categories by flow

Named outcomes from Step 3 (not capital projects):

Expansion

  • Building Addition
  • Building Replacement
  • Building Addition with Capital Investment
  • Policy Solution for Overcrowding

Maintenance / investment

  • Targeted Capital Investment
  • Standard Maintenance
  • Major Capital Investment

Closure / consolidation

  • Welcoming School
  • Welcoming School with Capital Investment
  • Closure (Goes to Welcoming School)
  • Welcoming School with Building Replacement

Step 4 — Prioritization

What it does

  • Ranks schools within selected strategy groups.
  • Metric weights (0–10) and disable checkboxes control influence on the priority score.
  • Results table supports flyout filters per group and a values/scores toggle.

Assumptions & methodology

  • Only schools in the selected group(s) are ranked; Step 3 assigns their category first.
  • Metrics are normalized (typically 0–100) across the active ranked set.
  • Priority score = (Σ normalizedScore × weight) / (Σ weight)
  • Show values = raw units; Show scores = normalized inputs. Ranking does not change when toggling.
  • Map markers are not sized by priority—prioritization is tabular.
Steps 3 and 4: Step 3 decides which pathway; Step 4 decides which schools to discuss first within that pathway.

School Project List

What it does

  • Separate page (school-profile.html) opened from the menu or Step 1.
  • Facility assets, FCI/deficiency context, modernization buckets, and Jeffco project history per school.

Assumptions & methodology

  • Uses facility and project CSVs documented under Data Sources (e.g. project list, deficiency exports).
  • Does not recalculate strategic sorting; may reference dashboard categories for context.
  • Refresh after updating source files to see new values.

When to use it

  • Steps 1–4 identify which schools matter; the Project List supports what it would take at the building level.

Read before updating data

DANGER ZONE

Decision export column names

If you rename column headers when editing 01 Decision Data Export.csv, the dashboard needs a small mapping file so it can still find each field. Edit that file by hand in Notepad or any text editor.

Original column (JSON key) — the name the dashboard expects, e.g. CurrEnrollment.
Updated column (JSON value) — the exact header in your saved CSV after you renamed it, e.g. Current_Enrollment.

Only list columns you actually renamed. If your CSV header still matches the original name, omit it. 

{
  "columns": {
    "CurrEnrollment": "Current_Enrollment"
  }
}

File: DecisionColumnMap.json in the same folder as index.html (inside JeffcoDashboard). Save the file, then restart the dashboard.

Display years on school cards (safe to edit)

There is one settings file: DashboardYearLabels.json in the same folder as index.html (inside JeffcoDashboard in the handoff package). It changes labels only (e.g. “Enrollment (2025)”) — not CSV column names or data values.

You do not need the steps below if you are only changing cell values (same file names, same headers). Use the rest of this guide only when column headers change, files are restructured, or a developer tool is required.

Run the dashboard

  1. Handoff zip: JeffcoDashboardDesktop.exe at the top level; index.html and Data Source inside the JeffcoDashboard subfolder (see scripts\build-handoff-package.ps1).
  2. Double-click Start-Jeffco-Dashboard.cmd or JeffcoDashboardDesktop.exe.
  3. No install step and no terminal commands.

Replace data files (most common update)

  • Copy updated CSV or GeoJSON files into Data Source (same names as listed in the tracker below).
  • Close and reopen the dashboard, or refresh the map page.
  • No scripts are required when you only change cell values or add rows.

Legacy header rename tool (optional)

This exe only converts old legacy headers (for example Enrollment2026 → CurrEnrollment) in bulk:

  1. JeffcoDataTools.exe lives in the JeffcoDashboard folder in the handoff package (next to index.html).
  2. Open Command Prompt in that folder (Shift + right-click → “Open in Terminal”).
  3. Run:
    JeffcoDataTools.exe migrate-decision-headers
  4. Or point at another folder:
    JeffcoDataTools.exe migrate-decision-headers --dashboard "C:\path\to\Jeffco_Dashboard"

This does the same job as npm run migrate:decision-stable-headers on a developer machine.
