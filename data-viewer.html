📋 Dashboard Overview

The Jeffco Schools Dashboard is a planning tool that helps compare facilities, capacity, and program needs across schools. It supports two major steps:

  • Strategy Sorting (Step 1) routes each school into a recommended strategy category using thresholds and score-based decision logic.
  • Prioritization (Step 2) ranks schools within a selected strategy group using weighted criteria.

✅ Key features

  • Interactive map to explore schools spatially (filters, popups, overlays).
  • Flowchart to explain “why” a school lands in its Step 1 category.
  • Impact analysis / model simulation to simulate reassignment outcomes for a selected sending school.
  • School Profile to review per-school projects and cost rollups (including priority subtotals).
  • Closure Scenarios to reassign students using student home coordinates + seat availability.
Tip: Each key feature has its own tab above with the logic and assumptions.

🏷️ Decision Categories

Decision Categories are the named outcomes produced by Strategy Sorting (Step 1). They summarize the recommended planning pathway for each school.

How to interpret categories

  • Categories are not projects: they describe the recommended pathway (expand, invest, consolidate), not a final design.
  • Categories depend on thresholds: changing sliders can change the category.
  • Step 2 uses categories: prioritization ranks within a selected category group.

Categories by flow

🟢 Expansion

  • Building Addition — address capacity via on-site expansion.
  • Building Replacement — replacement recommended to address needs.
  • Building Addition with Capital Investment — expansion plus significant investment.
  • Policy Solution for Overcrowding — address through policy/reassignment rather than construction.

🟠 Maintenance / Investment

  • Targeted Capital Investment — targeted improvements.
  • Standard Maintenance — routine maintenance needs.
  • Major Capital Investment — major improvements.

🔴 Closure / Consolidation

  • Welcoming School — candidate receiving school.
  • Welcoming School with Capital Investment — receiving school with improvements needed.
  • Closure (Goes to Welcoming School) — sending school recommended for closure and reassignment.
  • Welcoming School with Building Replacement — receiving school requires replacement.

🧭 Strategy Sorting (Step 1)

Goal: route each school into a Decision Category (Expansion, Maintenance/Investment, or Closure/Consolidation) using thresholds and score-based logic.

How Step 1 is structured

Flow 1: Decision Routing

Determines which planning pathway the school enters based on utilization, growth, and distance context.

Flow 2: Expansion

Evaluates whether capacity needs should be addressed through addition, replacement, investment + addition, or policy solution.

Flow 3: Maintenance / Investment

Classifies needs into Standard Maintenance, Targeted Capital Investment, or Major Capital Investment.

Flow 4: Closure / Consolidation

Evaluates consolidation/closure pathways and identifies welcoming schools and investment needs.

Building Composite Score (weighted)

The Building Composite Score is computed as a weighted combination of:

  • FCI — 30%
  • EUI — 15%
  • Building age — 15%
  • Year of last major renovation — 10%
  • Facility condition survey score — 10%
  • Work order data — 20%

📊 Flowchart (Step 1)

The interactive flowchart is a visual explanation of Strategy Sorting (Step 1). It shows the selected school’s path through decision nodes and reflects the current threshold settings.

What it does

  • Shows the path a school takes through Step 1 decision logic.
  • Displays thresholds at decision points (as currently set in the UI).
  • Helps interpret outcomes (why a school landed in a specific Decision Category).

What it does not do

  • Does not prioritize schools (that’s Step 2).
  • Does not estimate costs (that’s School Profile).

Node types (visual language)

🗺️ Decision Nodes

Decision points with Yes/No outcomes (a metric compared to a threshold).

🟠 Routing Nodes

Routing steps that direct the school into a specific flow.

🟢 Start Nodes

The start of a decision sub-flow.

🟣 Outcome Nodes

Final category outcomes for Step 1.

⚫ Threshold Nodes

Threshold/value display nodes for transparency and interpretation.

🏁 Prioritization (Step 2)

Goal: rank schools within a selected strategy group to support sequencing and investment conversations.

How scoring works (conceptually)

  • Within-group ranking: the ranked set depends on which strategy group is selected.
  • Normalization: metrics are scaled to comparable scores (typically 0–100) across the ranked set.
  • Weighted combination: normalized scores are combined using the active slider weights.
priorityScore = (Σ (normalizedMetricScore × metricWeight)) / (Σ metricWeight)

“Values” vs “Scores” (table display)

  • Show values: raw units (miles, %, counts).
  • Show scores: normalized values used in the weighting.
How it connects to Step 1: Step 1 decides the category; Step 2 decides the order within a chosen category group.

🗺️ Map & Layers

The map is the primary exploration UI. It combines school point data with decision outputs and optional overlays.

Core map behaviors

  • School points are colored by decision category/flow.
  • Popups provide key attributes and quick navigation.
  • Filtering narrows the displayed set (flow, level, enrollment, seats, etc.).
  • Layer order: base map (bottom) → overlays (e.g., articulation areas) → school points (top).

Articulation Areas overlay

  • Toggle in the map filter dropdown.
  • Styling is translucent so you can still see the base map + school points.
  • Interaction: hover/click shows the articulation area name and the list of schools in that area.

🏫 School Profile

The School Profile page summarizes project items and costs for a selected school. It uses the unit cost library to categorize projects and the school project list to populate per-school values.

What it outputs

  • Project list table with category, priority, unit cost/measure, and computed costs.
  • Total cost rollup plus Total Low / Total Medium / Total High priority subtotals.
  • Condition score status as Good, Poor, or N/A when not relevant.

Key rules

  • Category + measure + unit cost come from UnitCostLibrary.csv.
  • UnitValue + score values come from JeffCoProjectListAllSchools.csv.
  • Condition score compares the school’s numeric score to the library threshold value to determine Good/Poor (with a few category-specific direction rules).
  • Relevance: some rows (e.g., Gut Renovation / New Construction) are only relevant for certain Step 1 outcomes.

🚪 Closure Scenarios

The Closure Scenarios dashboard simulates closure of a sending school and reassigns students to receiving schools using distance and seat availability rules.

Inputs

  • Student roster: OD_Students.csv (home coordinates + current school).
  • School coordinates: Map_Export.csv.
  • Seats / enrollment: Decision Data Export.csv.
  • Grade spans: inferred from SchooltoSchoolDistances.csv.

Assignment logic (summary)

  • Distance: crow-fly miles from student home → candidate school.
  • Capacity: can respect available seats or allow overfill (if selected).
  • Grades: enforce overlapping grades or allow non-overlap and track added grades.
  • Min/Max miles: optional filters, with a “soft max” option that allows beyond max when needed.

Outputs

  • KPIs for impacted/assigned/unassigned, baseline miles vs scenario miles, and scenario max miles (home→new).
  • Destination summary table and CSV export.
  • Map visualization showing the closed school, destination schools, and flow lines.
